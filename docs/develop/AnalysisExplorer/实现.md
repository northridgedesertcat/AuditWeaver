## 0.1 本服务定位

`agent_service` 是 **AuditWeaver 系统中承载所有 Agent 的统一服务**,不是单一 Agent。

- 第一版只实现 **Analysis Explorer Agent**(对话式安全分析),但目录结构、路由、共享层都按"未来会有 N 个 Agent"设计。
- 后续新 Agent(如日志解释 Agent、规则建议 Agent、自动处置 Agent)只需要:
  1. 在 `agent_service/agents/` 下新增一个子包(写 graph / prompts / nodes)。
  2. 在 `agent_service/registry.py` 注册一个 `agent_type` 字符串。
  3. 路由 `/agent/{agent_type}/chat` 自动可用。
- 共享层(LLM 抽象、MCP Skills、会话历史、FastAPI 后端)只写一次,所有 Agent 复用。

## 3. Agent 注册与路由

### 3.1 Agent 注册表(`registry.py`)

```python
from typing import Callable, Dict
from langgraph.graph.state import CompiledStateGraph

# 每个 agent 注册一个工厂函数,返回编译好的 graph
AgentFactory = Callable[[], CompiledStateGraph]

_REGISTRY: Dict[str, AgentFactory] = {}

def register_agent(agent_type: str, factory: AgentFactory):
    """供 agents/<name>/__init__.py 调用,启动时自动注册。"""
    _REGISTRY[agent_type] = factory

def get_agent(agent_type: str) -> CompiledStateGraph:
    if agent_type not in _REGISTRY:
        raise ValueError(f"Unknown agent_type: {agent_type}")
    return _REGISTRY[agent_type]()

def list_agent_types() -> list[str]:
    return list(_REGISTRY.keys())
```

### 3.2 自动注册(`agents/__init__.py`)

```python
# 启动时遍历所有 agent 子包,触发它们各自的 register()
from . import analysis_explorer  # noqa: F401  (后续新增 agent 在此加一行)
```

### 3.3 单个 Agent 的注册(`agents/analysis_explorer/__init__.py`)

```python
from ..registry import register_agent
from .graph import build_graph

def _factory():
    # 每次 build 一次新 graph,保证 checkpointer 隔离
    return build_graph()

register_agent("analysis_explorer", _factory)
```

> 后续新增 Agent(例如 `rule_advisor`):只需新建 `agents/rule_advisor/` 子包,在 `agents/__init__.py` 加一行 `from . import rule_advisor`。

## 4. Analysis Explorer Agent 设计

> 本节是第一版要实现的 Agent,放在 `agents/analysis_explorer/`。

### 4.1 LangGraph 状态机

采用 **tool-calling ReAct 单层结构**(够用且可调试):

```text
                ┌──────────────────┐
   用户消息 ───▶│  agent_node      │  LLM 决策:直接回答 or 调 tool
                │  (bind_tools)    │
                └────────┬─────────┘
                         │
              ┌──────────┴──────────┐
              │ tool_calls 为空?     │
              └──────────┬──────────┘
                ┌────────┴────────┐
              是│                 │否
                ▼                 ▼
        ┌──────────────┐  ┌────────────────┐
        │ END (返回)    │  │ tools_node     │  执行 MCP 工具
        └──────────────┘  └────────┬────────┘
                                   │
                                   └──▶ agent_node (再决策)
```

- **state**:`{ messages: list[BaseMessage], thread_id: str }`,使用 LangGraph `MessagesState`。
- **agent_node**:把消息列表交给 LLM,LLM 通过 `bind_tools` 选择 0~N 个 Skill 调用。
- **tools_node**:用 LangGraph 预置 `ToolNode`,实际工具是 MCP Client 包装。
- **checkpointer**:用 `shared/memory/in_memory.py` 的 `MemorySaver`(一版),通过 `get_checkpointer()` 工厂取得。
- **max_tool_rounds**:防止 LLM 反复调工具不结束,默认 5 轮后强制停止。

### 4.2 LLM 抽象层(`shared/llm/`)

**设计目标**:同一份代码,通过 `.env` 配置切换 LLM 厂商,所有 Agent 复用。

`base.py`:
```python
from abc import ABC, abstractmethod
from langchain_core.language_models import BaseChatModel

class BaseLLMProvider(ABC):
    """LLM 提供方抽象。所有实现返回 langchain 的 BaseChatModel,
    这样上层的 bind_tools / astream 不感知具体厂商。"""
    @abstractmethod
    def build(self) -> BaseChatModel: ...
```

`openai_compat.py`(覆盖 DeepSeek / Qwen / GLM / Kimi / OpenAI 官方):
```python
from langchain_openai import ChatOpenAI
from .base import BaseLLMProvider
from shared.config.settings import LLM_CONFIG

class OpenAICompatProvider(BaseLLMProvider):
    """所有 OpenAI 兼容厂商走这一份实现,差异只在 base_url / model / api_key。"""
    def build(self) -> BaseChatModel:
        return ChatOpenAI(
            model=LLM_CONFIG['model'],
            base_url=LLM_CONFIG['base_url'],
            api_key=LLM_CONFIG['api_key'],
            temperature=LLM_CONFIG['temperature'],
            streaming=True,
        )
```

`factory.py`:
```python
from .openai_compat import OpenAICompatProvider
from shared.config.settings import LLM_CONFIG

def get_llm():
    provider = LLM_CONFIG['provider']
    # 一版只支持 openai_compat(覆盖大多数国产 OpenAI 兼容 API)
    # 后续如要接 Anthropic / Bedrock / 自部署 vLLM,在此分支即可
    if provider == 'openai_compat':
        return OpenAICompatProvider().build()
    raise ValueError(f"Unknown LLM provider: {provider}")
```

`shared/config/settings.py` 读 `.env`:
```python
from common.env import get_env, get_env_float

LLM_CONFIG = {
    'provider': get_env('AE_LLM_PROVIDER', 'openai_compat'),
    'base_url': get_env('AE_LLM_BASE_URL'),
    'api_key': get_env('AE_LLM_API_KEY'),
    'model':   get_env('AE_LLM_MODEL', 'deepseek-chat'),
    'temperature': get_env_float('AE_LLM_TEMPERATURE', 0.2),
}
```

**切换模型示例**(只改 `.env`,不动代码):
```env
# DeepSeek
AE_LLM_BASE_URL=https://api.deepseek.com/v1
AE_LLM_MODEL=deepseek-chat

# Qwen
AE_LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
AE_LLM_MODEL=qwen-plus

# GLM
AE_LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
AE_LLM_MODEL=glm-4-plus
```

### 4.3 MCP Client(`shared/mcp_client.py`)

- 使用 `langchain-mcp-adapters` 把 MCP Server 暴露的工具转成 LangChain `Tool` 列表。
- 连接方式 stdio:Agent Service 进程子进程拉起 `python -m services.agent_service.skills.server`。
- Agent Service 与 Skills 同机部署,无需额外端口。
- 工具列表缓存,所有 Agent 共用同一个 MCP 连接。

### 4.4 会话历史(`shared/memory/`)

一版:
- `in_memory.py`:LangGraph `MemorySaver`,进程内字典。
- 通过 `get_checkpointer()` 统一拿,业务代码不直接 new。
- 进程重启会丢历史(可接受)。
- 每个 `agent_type` 使用独立的 checkpointer 命名空间,避免不同 Agent 的对话串。

预留扩展点(一版不实现):
- `redis.py`:`RedisSaver`(LangGraph 官方实现),后续接 Redis 即可。
- 接口签名一致,业务代码不变。

## 5. Skills 详细设计(MCP)

> Skills 放在 `shared/skills/`,不绑定某个 Agent。一版服务 Analysis Explorer,后续其他 Agent 也可复用。

### 5.1 MCP Server 入口(`skills/server.py`)

```python
from mcp.server.fastmcp import FastMCP
from .query_ip_logs import query_ip_logs
from .query_analysis_results import query_analysis_results
from .query_security_events import query_security_events

mcp = FastMCP("agent-service-skills")

mcp.tool()(query_ip_logs)
mcp.tool()(query_analysis_results)
mcp.tool()(query_security_events)

if __name__ == "__main__":
    mcp.run(transport="stdio")
```

### 5.2 Skill 1:QueryIPLogs

- **数据源**:`nginx-log-raw`
- **入参**:

| 参数         | 类型   | 必填 | 默认    | 说明                        |
| ------------ | ------ | ---- | ------- | --------------------------- |
| `ip`         | string | 是   | -       | 目标 IP                     |
| `time_range` | string | 否   | `24h`   | `15m`/`1h`/`24h`/`7d`/`all` |
| `size`       | int    | 否   | 50      | 返回条数上限(≤ 200)        |

- **ES 查询**:`bool.must = [{term:{ip}}, {range:{"@timestamp":{gte, lte}}}]`,`sort: @timestamp desc`。
- **返回**:
  ```json
  {
    "ip": "192.168.1.100",
    "total": 1247,
    "returned": 50,
    "time_range": "24h",
    "logs": [
      {"timestamp": 1726370000000, "method": "POST", "path": "/login",
       "status": 401, "user_agent": "...", "event_id": "..."}
    ]
  }
  ```

### 5.3 Skill 2:QueryAnalysisResults

- **数据源**:`log_analysis_reports`
- **入参**:

| 参数         | 类型   | 必填 | 默认   | 说明                                   |
| ------------ | ------ | ---- | ------ | --------------------------------------- |
| `ip`         | string | 否   | -      | 不传则查所有 IP                         |
| `risk_level` | string | 否   | `all`  | `Critical/High/Medium/Low/Normal/all`   |
| `time_range` | string | 否   | `24h`  | 同上                                    |
| `size`       | int    | 否   | 20     | ≤ 100                                   |

- **ES 查询**:`bool.must` 组合 `term:{ip}`、`terms:{risk_level}`、`range:{analysis_timestamp}`,`sort: analysis_timestamp desc`。
- **返回**:报告摘要数组(每个含 `event_id, ip, attack_type_ai, risk_level, risk_score, summary, analysis_timestamp`)。

### 5.4 Skill 3:QuerySecurityEvents

- **数据源**:`matched_logs`
- **入参**:

| 参数          | 类型   | 必填 | 默认   | 说明                                    |
| ------------- | ------ | ---- | ------ | --------------------------------------- |
| `attack_type` | string | 否   | `all`  | `sql_injection/xss/path_traversal/...`  |
| `ip`          | string | 否   | -      |                                         |
| `time_range`  | string | 否   | `24h`  |                                         |
| `size`        | int    | 否   | 50     | ≤ 200                                   |

- **ES 查询**:`bool.must` 组合 `term:{attack_type}`、`term:{log_context.ip}`、`range:{log_context.timestamp}`。
- **返回**:事件数组(含 `event_id, attack_type, ip, path, method, status, matched_value, rule_id, timestamp`)。

### 5.5 通用约束

- 所有 Skill 只读,不写 ES。
- 时间范围解析统一用 `common.time_utils`(沿用项目既有工具)。
- ES Client 用 `skills/es.py` 共用,配置从 `common.env` 读(沿用现有 `ES_HOST/ES_PORT/...`)。
- Skill 返回结构里**不要包含 `_score`、`_index` 等 ES 内部字段**,前端不需要。

## 6. FastAPI 后端(对内)

### 6.1 接口列表

| 方法 | 路径                              | 说明                                       |
| ---- | --------------------------------- | ------------------------------------------ |
| POST | `/agent/{agent_type}/chat`        | 流式对话(SSE),Django 主用                 |
| POST | `/agent/{agent_type}/chat/sync`   | 非流式对话(返回完整 JSON)               |
| GET  | `/agent/health`                    | 健康检查                                    |

### 6.2 请求 / 响应

### 6.3 后端职责边界(对齐需求第 5 节)

- FastAPI **只做**:
  - HTTP/SSE 协议层
  - 请求校验(Pydantic)
  - 流式 token 转发
  - 错误处理与超时控制
  - thread_id 透传给 agent
  - 按 `agent_type` 从 `registry` 取对应 graph
- FastAPI **不做**:
  - LLM 调用
  - 工具调用
  - 业务逻辑
- 这些都在 Agent 模块内完成,FastAPI 通过 `graph.astream(...)` 拿到事件流直接透传。

### 7.2 反代视图

新增 `AgentProxyView`,用 `StreamingHttpResponse` 透传 SSE 流(关键是不要用 `requests`,要用 `httpx` 的 streaming):

```python
import httpx
from django.http import StreamingHttpResponse, JsonResponse
from rest_framework.views import APIView
from django.conf import settings

FASTAPI_BASE = settings.AGENT_FASTAPI_BASE  # "http://127.0.0.1:8001"

class AgentProxyView(APIView):
    """Django → FastAPI 反代。透传请求体和 SSE 流,保留 agent_type 路径段。"""
    permission_classes = []

    def _build_target(self, request, sub_path=""):
        # request.path_info 形如 /api/v1/agent/analysis_explorer/chat
        # 截掉 /api/v1 前缀,拼到 FastAPI base
        prefix = "/api/v1"
        tail = request.path_info[len(prefix):]  # /agent/analysis_explorer/chat
        return f"{FASTAPI_BASE}{tail}"

    def post(self, request, *args, **kwargs):
        target = self._build_target(request)
        def stream():
            with httpx.stream("POST", target, json=request.data, timeout=None) as r:
                for chunk in r.iter_bytes():
                    yield chunk
        resp = StreamingHttpResponse(stream(), content_type="text/event-stream")
        resp["X-Accel-Buffering"] = "no"  # 禁用 nginx 缓冲,保证 SSE 实时
        return resp

    def get(self, request, *args, **kwargs):
        target = self._build_target(request)
        r = httpx.get(target, timeout=10)
        return JsonResponse(r.json(), status=r.status_code)
```

> 关键:通过 `request.path_info` 截取后缀,完整保留 `agent_type` 和子路径,这样 Django 端不需要为每个 agent 单独配路由。

## 9. 完整案例(对齐需求第 3 节)

用户输入:`192.168.1.100 最近有什么危险行为?`

```text
1. 前端 → POST /api/v1/agent/analysis_explorer/chat (Django)
   { message, thread_id }
   URL 中的 analysis_explorer 即 agent_type

2. Django AgentProxyView → POST /agent/analysis_explorer/chat (FastAPI :8001)
   透传请求体和 SSE 流

3. FastAPI 从 registry 拿 analysis_explorer 的 graph
   → graph.astream(messages)
   agent_node:
     LLM 决定先查日志 → tool_calls=[QueryIPLogs(ip=192.168.1.100, time_range=24h)]

4. tools_node → MCP Client → skills/server.py
   query_ip_logs 执行 ES 查询 nginx-log-raw
   返回 {total: 1247, logs: [...]}

5. agent_node (第二轮):
     LLM 看到日志量大且多为 401,决定查分析结果
     tool_calls=[QueryAnalysisResults(ip=192.168.1.100, risk_level=High)]

6. tools_node → skills
   query_analysis_results 查 log_analysis_reports
   返回 [{attack_type_ai: Brute Force, risk_level: High, summary: ...}]

7. agent_node (第三轮):
     LLM 综合两边结果产出最终自然语言回答

8. FastAPI SSE 流 → Django StreamingHttpResponse 透传 → 前端逐 token 渲染:
   "该 IP 最近 24 小时产生 1247 条访问请求,
    其中 90% 为 401 登录失败;日志分析 Agent 判定为疑似暴力破解,
    风险等级 High。建议:封禁该 IP / 加固登录接口 / 启用 MFA。"
```
