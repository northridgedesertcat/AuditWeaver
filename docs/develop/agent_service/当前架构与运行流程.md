## 0. 一句话定位

Agent Service 是 AuditWeaver 的对话式安全分析模块:**用户在前端用自然语言问 IP 行为 / 攻击事件 / 分析报告,FastAPI + LangGraph + MCP 把请求转成"LLM 决策 → 查 ES → 总结"的循环,通过 SSE 流式返回**。服务监听 `127.0.0.1:8001` 对内只服务 Django,不直接对外。

**分层原则**:
- `backend/` 只做协议层(HTTP / SSE),不含 LLM 调用逻辑
- `agents/` 只做单 Agent 的图组装与节点实现
- `shared/` 是所有 Agent 共用的基础设施(LLM / Memory / MCP / 配置)
- `skills/` 是 MCP Server + 工具实现,与 Agent 解耦
- `registry.py` 是 Agent 路由层,backend 与 agents 之间的桥梁

## 4. 核心数据模型

### 4.1 Agent 状态:AgentState

```python
from langgraph.graph import MessagesState

class AgentState(MessagesState):
    pass
```
> [state.py](file:///d:/tools/ProgrammeTools/python/正规项目/AuditWeaver/services/agent_service/agents/analysis_explorer/state.py)

继承 LangGraph 的 `MessagesState`,自带:
- 字段 `messages: list[BaseMessage]`
- 归约器 `add_messages`(节点返回 `{"messages": [新消息]}` 时**追加**到历史,不是覆盖)

子类 `pass` 是**预留扩展点**:之后要加中间结构化字段(如 `tool_call_count`、`risk_summary`)只要在子类加字段 + 自定义 reducer。

### 4.2 消息类型(LangChain Core)

| 类型 | 来源 | 用途 |
|------|------|------|
| `SystemMessage` | `prompts.SYSTEM_PROMPT` | 每轮 agent_node 前置,锁角色约束 |
| `HumanMessage` | 前端 `ChatRequest.message` + `history` | 用户输入 |
| `AIMessage` | `_llm_with_tools.ainvoke` 输出 | LLM 决策:可能带 `tool_calls` 字段 |
| `ToolMessage` | `ToolNode.ainvoke` 输出 | 工具结果,`tool_call_id` 关联到原 tool_call |

`AIMessage.tool_calls` 字段结构:`[{name: str, args: dict, id: str}]`(LLM 一次可以发起多个 tool_calls,ToolNode 并发执行)。

### 4.3 HTTP 请求 / 响应(Pydantic)

> [schemas.py](file:///d:/tools/ProgrammeTools/python/正规项目/AuditWeaver/services/agent_service/backend/schemas.py)

```python
class ChatRequest(BaseModel):
    message: str                       # 用户输入(必填)
    thread_id: str | None             # 会话 ID;None 则单次无状态
    history: list[dict]                # 可选历史消息 [{role, content}]

class ChatSyncResponse(BaseModel):
    agent_type: str
    answer: str                        # 最后一条 AIMessage.content
    tool_calls: list[dict]             # [{tool, args, summary}]
    thread_id: str | None
```

### 4.4 SSE 事件结构(stream.py 产出)

每行 `data: {json}\n\n`,字段 `type` 区分:

| type | 何时产出 | 字段 |
|------|----------|------|
| `token` | `on_chat_model_stream`(LLM 输出 chunk) | `content: str` |
| `tool_call` | `on_tool_start`(工具开始执行) | `tool: str, args: dict` |
| `tool_result` | `on_tool_end`(工具结束) | `tool: str, summary: str`(摘要,非原始 JSON) |
| `error` | 任何异常 | `content: str` |
| `done` | 流结束 | (无字段) |

> [stream.py](file:///d:/tools/ProgrammeTools/python/正规项目/AuditWeaver/services/agent_service/backend/stream.py#L73-L112)

### 4.5 ES 索引与字段

Skills 直接查询 ES 已有索引,索引名来自 [common/env.py](file:///d:/tools/ProgrammeTools/python/正规项目/AuditWeaver/common/env.py#L96-L98):

| 索引名 | env 变量 | Skill | 关键字段(被 Skill 读取) |
|--------|---------|-------|--------------------------|
| `nginx-log-raw` | `ES_INDEX_NGINX_RAW` | query_ip_logs | `@timestamp`、`ip`、`method`、`path`、`status`、`user_agent`、`event_id` |
| `matched_logs` | `ES_INDEX_MATCHED_LOGS` | query_security_events | `event_id`、`attack_type`、`log_context.{ip,path,method,status,timestamp}`、`detections[].rule_id`、`detections[].matches[].matched_value` |
| `log_analysis_reports` | `ES_INDEX_ANALYSIS_REPORTS` | query_analysis_results | `event_id`、`ip`、`attack_type_ai`、`risk_level`、`risk_score`、`summary`、`analysis_timestamp` |

> 注:这些索引由既有 `Kafka → Logstash → Kafka → Kafka Connect Sink → ES` 管线写入,Agent 只读。Agent 不直接消费 Kafka。

### 4.6 Skill 返回结构(三个 Skill 一致的模式)

每个 Skill 返回 `dict`,失败时不抛异常,返回带 `error` 字段的降级结构:

```python
# 成功
{
    "<key>": <过滤条件回显>,
    "total": <总条数>,
    "returned": <返回条数>,
    "time_range": <时间范围回显>,
    "<数据键>": [ {...}, ... ]   # logs / events / reports
}

# ES 不可用 / 查询异常
{
    "<key>": <过滤条件回显>,
    "total": 0,
    "returned": 0,
    "<数据键>": [],
    "error": "elasticsearch unavailable"
}
```

| Skill | 过滤条件回显字段 | 数据键 |
|-------|----------------|---------|
| query_ip_logs | `ip` | `logs` |
| query_security_events | `attack_type`、`ip` | `events` |
| query_analysis_results | `ip`、`risk_level` | `reports` |

`MAX_SIZE_RAW=200` / `MAX_SIZE_REPORTS=100` / `MAX_SIZE_EVENTS=200`(`size` 参数会被 `min/max` 钳到上限)。

## 5. 运行流程

### 5.1 启动流程

```
start.py
   │
   │ (健康检查 + 全栈编排,见 [scripts/docker_manager.py])
   ▼
uvicorn services.agent_service.backend.main:app --host 127.0.0.1 --port 8001
   │
   │ 1. main.py 把 _AGENT_SERVICE_DIR + _PROJECT_ROOT 加入 sys.path
   │    (确保 shared/ agents/ skills/ registry/ common 都可解析)
   │
   │ 2. import agents  ← 触发 agents/__init__.py
   │    └─ from . import analysis_explorer
   │         └─ analysis_explorer/__init__.py 调
   │            register_agent("analysis_explorer", _factory)
   │            (_factory = lambda: build_graph())
   │
   │ 3. app = FastAPI(...)
   │    app.include_router(health_routes)  ← /agent/health, /agent/types
   │    app.include_router(agent_routes)  ← /agent/{type}/chat, /chat/sync
   │
   ▼
uvicorn 接受请求,首次命中 /agent/{type}/chat 时:
   │
   │ 4. deps.get_graph(agent_type)
   │    └─ registry.get_agent(agent_type) → factory() → build_graph()
   │       └─ build_graph() 内部 graph.compile(checkpointer=get_checkpointer())
   │          · get_checkpointer() 读 AE_MEMORY_BACKEND
   │            (默认 memory → MemorySaver;redis 预留未实现)
   │
   │ 5. 首次调用 agent_node 时触发 _ensure():
   │    · get_llm()  ← factory 按 AE_LLM_PROVIDER 选 OpenAICompatProvider
   │                   · ChatOpenAI(model, base_url, api_key, temperature, Streaming=True)
   │    · get_mcp_tools()
   │       └─ MultiServerMCPClient.get_tools()
   │          · 拉起子进程:python -m services.agent_service.skills.server
   │          · skills/server.py 内 mcp.run(transport="stdio")
   │          · 返回 list[BaseTool](三个 Skill 已适配)
   │    · _llm_with_tools = _llm.bind_tools(tools)
   │    · _tools_node = ToolNode(tools)
   │    · 缓存到进程内单例,后续所有请求复用
   │
   ▼
就绪,接受对话请求
```

> 关键点:`uvicorn` 必须从**项目根目录**启动,否则 Skills 子进程 `import common` 失败。注释见 [mcp_client.py](file:///d:/tools/ProgrammeTools/python/正规项目/AuditWeaver/services/agent_service/shared/mcp_client.py#L8-L10)。

### 5.2 请求流程(流式,主用)

```
前端 EventSource POST /api/v1/agent/analysis_explorer/chat
   │
   ▼ Django 反代(AGENT_FASTAPI_BASE = http://127.0.0.1:8001)
   │   StreamingHttpResponse 透传 SSE
   │
   ▼ FastAPI routes/agent.py:chat(agent_type, req: ChatRequest)
   │
   │ 1. _resolve_graph(agent_type)
   │    ├─ deps.get_graph(agent_type)
   │    │  └─ registry.get_agent(agent_type)
   │    │     ├─ 命中:factory() → build_graph() 返回新编译的 CompiledStateGraph
   │    │     └─ 未命中:raise ValueError → 路由层转 HTTPException(404)
   │
   │ 2. StreamingResponse(stream_agent_chat(graph, agent_type, message, thread_id, history),
   │                       media_type="text/event-stream",
   │                       headers={"Cache-Control":"no-cache","X-Accel-Buffering":"no"})
   │
   ▼ stream_agent_chat(graph, ...)
   │
   │ 3. _namespaced_thread(agent_type, thread_id) → "{agent_type}:{thread_id}"
   │    (没有 thread_id 时返回 None,走单次无状态)
   │
   │ 4. config = {"configurable": {"thread_id": ns_thread}} if ns_thread else {}
   │
   │ 5. inputs = _build_inputs(message, history, thread_id):
   │    ├─ 有 thread_id: {"messages": [HumanMessage(message)]}
   │    │  (历史由 checkpointer 维护)
   │    └─ 无 thread_id: history 前置拼成消息列表 + 末尾追加 HumanMessage
   │
   │ 6. async for event in graph.astream_events(inputs, config=config, version="v2"):
   │    ├─ on_chat_model_stream → yield sse_line({"type":"token","content":...})
   │    ├─ on_tool_start        → yield sse_line({"type":"tool_call","tool":...,"args":...})
   │    ├─ on_tool_end          → yield sse_line({"type":"tool_result","tool":...,
   │    │                                              "summary": _summarize_tool_output(...)})
   │    └─ 异常                 → yield sse_line({"type":"error","content":...})
   │
   │ 7. yield sse_line({"type":"done"})
   │
   ▼
前端 EventSource 逐行解析,token 累积渲染,tool_call/tool_result 实时展示
```

### 5.3 请求流程(非流式)

```
POST /api/v1/agent/analysis_explorer/chat/sync
   │
   ▼ routes/agent.py:chat_sync(agent_type, req)
   │
   │ run_agent_sync(graph, agent_type, message, thread_id, history)
   │
   │ 1. 同样的 thread_id 命名空间 + config 构造
   │ 2. final_state = await graph.ainvoke(inputs, config=config)
   │ 3. 从 final_state.messages 取最后一条 AIMessage.content 作为 answer
   │ 4. 遍历 messages 还原 tool_calls 清单:
   │    · AIMessage.tool_calls → {tool, args, summary:""}
   │    · ToolMessage.content → 反向匹配上一条未填 summary 的 tool_call
   │      用 _summarize_tool_output 填上摘要
   │
   ▼ 返回 ChatSyncResponse(agent_type, answer, tool_calls, thread_id)
```

### 5.4 Agent 内部循环(LangGraph 图执行)

每次 `astream_events` / `ainvoke` 进入图后的内部循环:

```
进入 agent 节点
   │
   ▼ agent_node(state)
   │ 1. await _ensure()(首次触发 LLM/MCP 加载,后续 no-op)
   │ 2. messages = [SystemMessage(SYSTEM_PROMPT)] + list(state["messages"])
   │ 3. response = await _llm_with_tools.ainvoke(messages)
   │    · LLM 决策:直接回答(content 是文本)or 发起 tool_calls
   │ 4. return {"messages": [response]}  ← add_messages 归约器追加
   │
   ▼ _route_after_agent(state)
   │ 1. last = state["messages"][-1]
   │ 2. has_tool_calls = bool(last.tool_calls)
   │ 3. tool_rounds = 统计历史 ToolMessage 数
   │ 4. if has_tool_calls and tool_rounds < MAX_TOOL_ROUNDS(5):
   │       return "tools"
   │    else:
   │       return END
   │
   ├─ "tools" ─────────────────────────────────────┐
   │                                                ▼
   │                                     tools_node(state)
   │                                     │ 1. await _ensure()
   │                                     │ 2. await _tools_node.ainvoke(state)
   │                                     │    · 消费上条 AIMessage.tool_calls
   │                                     │    · 并发执行所有 tool_calls(asyncio)
   │                                     │    · 每个 tool_call 经 MCP Client →
   │                                     │      stdio → FastMCP → Skill 函数 → ES
   │                                     │ 3. return {"messages": [ToolMessage, ...]}
   │                                     │
   │                                     └── 回到 agent_node(继续循环)
   │
   └─ END ──────────────────────────────────────────┐
                                                    ▼
                                          graph 结束,final_state 落定
                                          (astream_events 流尽,ainvoke 返回)
```

### 5.5 MCP / Skills 调用链路

```
ToolNode.ainvoke 调 BaseTool(MCP 适配的)
   │
   ▼ MultiServerMCPClient(langchain_mcp_adapters)
   │  · transport="stdio"
   │  · command=sys.executable(args: ["-m","services.agent_service.skills.server"])
   │  · 单例 _MCPHolder(asyncio.Lock + 双重检查)
   │
   ▼ stdio 子进程
   │  skills/server.py
   │  · mcp = FastMCP("agent-service-skills")
   │  · mcp.tool()(query_ip_logs)
   │  · mcp.tool()(query_analysis_results)
   │  · mcp.tool()(query_security_events)
   │  · mcp.run(transport="stdio")
   │
   ▼ FastMCP 路由到对应 Skill 函数
   │  (按 LLM 决策的 tool name + args 调用)
   │
   ▼ Skill 函数(query_*.py)
   │  · parse_time_range(time_range) → (gte, lte) epoch millis
   │  · 构造 ES query body(bool + must + range + sort)
   │  · search(index, body) → skills/es.py
   │    · 单例 ES 客户端(basic_auth + request_timeout=30 + max_retries=3 + retry_on_timeout=True)
   │    · 失败返回 None,不抛栈
   │  · 解析 hits,提取关键字段
   │  · 返回结构化 dict(见 4.6)
   │
   ▼ ToolMessage.content = dict(json 序列化)
   │
   ▼ stream.py:_summarize_tool_output 压成一句话("12 条记录")
   │  给前端展示用;LLM 那边继续看完整结果做归纳
   │
   ▼ 追加到 state.messages,回到 agent_node
```

### 5.6 多轮上下文(checkpointer)

```
首次请求(前端不传 thread_id)
   │
   ▼ _build_inputs 把 history 拼进 messages(单次无状态)
   ▼ config = {}(无 thread_id)
   ▼ graph 执行,checkpointer 不持久化(无 thread_id 时 LangGraph 视为单次)
   ▼ 返回结果
   │
   │ (前端拿到结果后,如果想继续追问,需要后端返回 thread_id,
   │  当前实现 ChatSyncResponse.thread_id 回显的是请求里的,
   │  即前端要自己生成并维护 thread_id 才能多轮)
   │
第二次请求(前端传 thread_id="abc")
   │
   ▼ _namespaced_thread → "analysis_explorer:abc"
   ▼ config = {"configurable":{"thread_id":"analysis_explorer:abc"}}
   ▼ _build_inputs:有 thread_id,只追加本轮 HumanMessage
   ▼ graph.astream_events / ainvoke:
   │  LangGraph 自动从 checkpointer 加载该 thread_id 的历史 messages
   │  + 本轮输入 → 进入 agent_node
   ▼ 执行后状态写回 checkpointer(进程内 MemorySaver)
   │
   ▼ 重启 FastAPI → MemorySaver 丢失,thread_id 失效(需重新对话)
```

> 关键点:`thread_id` 由**前端生成**并维护,后端只做命名空间隔离(`agent_type:` 前缀防不同 Agent 串话)。

   ```python
   def query_threat_intel(ip: str, ...) -> dict:
       """查询 IP 是否在威胁情报库中。"""

       resp = search(ES_INDEX_THREAT_INTEL, body)
   ```

5. **更新 system prompt**:在 [prompts.py](file:///d:/tools/ProgrammeTools/python/正规项目/AuditWeaver/services/agent_service/agents/analysis_explorer/prompts.py) 的工具说明里加一行,LLM 才知道何时调新 Skill。

   ```python
   if provider == 'anthropic':
       impl = AnthropicProvider()
   ```

## 9. 已知边界与未落地

> 这些是当前代码的真实状态,改动前先评估是否触及。

| 项 | 状态 | 影响 / 改动方向 |
|----|------|----------------|
| 多 Agent 协同 | ❌ 只有 `analysis_explorer` 一个 Agent | registry 已为多 Agent 预留扩展点,但 LangGraph 的 Multi-Agent Supervisor 模式未实现 |
| Redis checkpointer | ❌ `get_redis_saver()` 预留未实现 | `AE_MEMORY_BACKEND=redis` 会报错,只能用 `memory` |
| 长对话 context 窗口 | ❌ 未做消息摘要 / 滑动窗口 | 长对话会触发 LLM context limit,需在 agent_node 加摘要压缩逻辑 |
| RAG / 向量检索 | ❌ Skills 全是 ES `term`/`range` 精确查询 | 没接 `dense_vector` / kNN,要做需新增 `QuerySimilarReports` Skill + Embedding 索引构建管线 |
| vLLM 本地部署 | ❌ 未部署 | 代码层已支持(`OpenAICompatProvider` 接 OpenAI 兼容 API),部署是运维工作 |
| Skills 子进程重连 | ❌ 未做 | Skills 崩了 MCP Client 调用失败,Agent 拿到错误;生产级需加健康检查 + 重连 |
| Skills 热加载 | ❌ 新增 Skill 需重启 Agent Service | MCP Server 是常驻子进程,不能热加载 |
| Django 反代 SSE 代码 | 📋 设计在文档,具体反代路由代码 | FastAPI 端已落地,Django 端开发期可直接连 8001 验证 |
| LangSmith / Langfuse | ❌ 未接 | 调试靠 `astream_events` 事件流 + 非流式 `tool_calls` 清单 |
| SOAR / security_responder | ❌ 计划中 | 接收告警 → LLM 决策处置建议(封禁 IP / 加固规则),不真执行 |
| 流量分析 / NetFlow | ❌ 未做 | Skills 只查日志类索引,没接流量 |
| 威胁情报 / IoC | ❌ 未做 | 计划加 `threat_intel` 索引 + `QueryThreatIntel` Skill |
| ATT&CK 对齐 | ❌ 规则配置没加 `mitre_attack` 字段 | 安全研发面试高频词,简历没写就别提 |
